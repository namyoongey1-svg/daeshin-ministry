# 대신 교역자 사역자톡방

대신 교단 사역자를 위한 청빙·구직 및 설교 준비 플랫폼.

**배포 주소: https://daeshin-ministry.vercel.app**

소스는 공개되어 있습니다. 교단과 상관없이 가져다 쓰셔도 되고,
고칠 곳이 보이면 알려 주시거나 직접 고쳐 보내 주셔도 됩니다.

## 실행

```bash
npm install
npm run dev
```

원어 데이터(`src/data/`)는 저장소에 포함되어 있습니다. 다시 받으려면:

```bash
npm run import:bible          # 전체
npm run import:bible greek    # 헬라어만
```

## 청빙공고 수집

세 곳의 공개 게시판에서 공고 정보를 모읍니다.

매일 07:00(KST)에 GitHub Actions가 자동으로 돌립니다
(`.github/workflows/scrape.yml`). 저장소 Actions 탭에서 수동 실행도 됩니다.
손으로 돌릴 때는:

```bash
npm run scrape                 # 새 글이 없으면 멈춤 (정기 수집용)
npm run scrape -- godpeople    # 한 곳만
npm run scrape -- --full --pages 25
npm run scrape -- --prune 12   # 12개월 지난 공고는 버림
npm run scrape -- --delay 2000 # 요청 간격 조절
```

| 출처 | 게시판 | 특징 |
|---|---|---|
| `godpeople` | [갓피플취업](https://recruit.godpeople.com/?GO=recruit_find) | 지역·직분·부서 꼬리표가 붙어 분류가 가장 정확 |
| `baekseok` | [백석대 신대원 정보나눔터](https://www.bu.ac.kr/graduateschool/3938/subview.do) | 제목이 `[지역] 교회명` 꼴 |
| `aats` | [총신대 신대원 총동창회](http://aats.kr/main/bbs/board.php?bo_table=b05) | 제목 문장에서 직분을 추출 |

### 지역 거르기

**17개 시·도 + 시·군·구** 두 칸으로 고릅니다(`src/lib/region.ts`).
예전에는 "충남·대전·세종"처럼 묶어 12개로 두었는데, 대전에서 사역할 사람에게
천안 공고를 섞어 보여 주는 셈이었습니다.

여러 곳을 한꺼번에 담습니다 — 실제로 자리를 찾는 사람은 "분당 아니면 용인"처럼
두세 곳을 함께 봅니다. 고르는 칸에 **건수**를 함께 적어, 그곳에 공고가 있는지부터
알 수 있게 했습니다. 지역을 하나 고른 뒤에도 다른 지역 건수는 그대로 보입니다.

원문 표기는 제각각입니다 — `경기도 안양시`, `서울시 송파구`, `성남시 분당구`(시·도 없음),
`인천.서구`(구분자가 점), `강남구 대치동`(구부터), `호주 퍼스`. 수집본 131종을
모두 대본 결과 **592건 분류 / 못 읽음 2건**입니다(못 읽은 둘은 교회 이름이
지역 칸에 들어간 원문 오류입니다).

"전국"과 "○○ 외"는 지역이 아닙니다. 갓피플의 "서울 외"은 서울이 아니라 서울
밖이라는 뜻이라, 그대로 두면 수도권 밖 교회가 전부 서울로 잡힙니다.

지역은 저장된 값이 아니라 **볼 때마다 원문 표기에서 다시 읽습니다.** 그래야 규칙을
고칠 때 다시 수집하지 않아도 이미 모인 공고까지 함께 바뀝니다.

### 한 곳이 안 될 때

세 곳 중 한 곳이 안 되는 날이 있습니다. 상대 게시판이 잠깐 내려가거나,
GitHub의 실행 서버(미국)에서 국내 주소로 가는 길이 막히는 경우입니다.

**한두 곳이 실패해도 수집은 성공으로 칩니다.** 나머지 곳의 공고는 그대로
들어오기 때문입니다. 흔들릴 때마다 실패 메일이 오면 정작 다 끊긴 날을
놓치게 됩니다. `npm run scrape` 가 1로 끝나는 것은 **세 곳이 모두 실패한
날**뿐입니다.

대신 어디가 왜 안 됐는지는 실행 페이지 맨 위 요약에 표로 남습니다
(`GITHUB_STEP_SUMMARY`). 이유에는 `ENOTFOUND`, `ECONNREFUSED`,
`20초 안에 응답이 없음`처럼 원인까지 적힙니다 — `fetch failed` 한 줄만으로는
손을 쓸 수 없기 때문입니다. **요약은 로그와 달리 로그인 없이 보입니다.**

### 수집하는 것과 하지 않는 것

모으는 항목은 **교회명·지역·직분·부서·게시일·마감일과 원문 링크**입니다.
**게시물 본문과 담당자 연락처는 가져오지 않습니다.** 본문은 작성자의 저작물이고
연락처는 개인정보라, 사용자가 원문 게시판으로 가서 보도록 링크만 겁니다.
요청은 1.2초 간격으로 보내고, 출처와 연락처를 밝힌 User-Agent를 씁니다.

### 같은 공고를 두 번 담지 않기

**갓피플의 `rc_idxx`는 고정 글번호가 아니라 요청마다 새로 발급되는 토큰입니다.**
같은 공고를 두 번 받으면 토큰이 서로 다릅니다. 이걸 식별자로 쓰면 수집할 때마다
424건이 통째로 새 글로 쌓입니다. 그래서 갓피플만은 `교회명 + 제목`을 해시한 값을
식별자로 씁니다(`stableId`). 먼저 받은 토큰으로도 원문은 계속 열리므로, 링크는
처음 본 값을 그대로 둡니다 — 매일 커밋하는데 링크가 날마다 바뀌면 바뀐 것이 없는
날에도 수백 건이 다시 쓰이기 때문입니다.

교회들은 목록 위로 올리려고 같은 공고를 여러 번 다시 올립니다(한 목록 안에서
17번까지 올라온 경우가 있습니다). 화면에서는 하나로 묶고 **재게시 횟수**를 함께
보여 줍니다 — 재게시가 잦다는 것은 아직 사람을 못 구했다는 신호이기 때문입니다.

### 마감 처리

갓피플 목록은 "현재 모집 중인 공고 전체"를 뜻하므로, 끝까지 훑은 뒤 목록에서
사라진 공고는 마감(`closedAt`)으로 표시하고 `/jobs`에서 감춥니다.
백석대·총신대는 지난 글도 계속 남아 있는 게시판이라 사라짐을 마감으로 보지
않습니다(`activeListing` 플래그로 구분).

수집 결과는 `src/data/scraped/posts.json`에 쌓입니다. Supabase로 옮길 때는
`supabase/scraped_posts.sql`을 실행하세요.

## 찬양 콘티

`/tools/setlist`. 곡 순서와 조, 연결을 정리하고 **단톡방에 그대로 붙일 글**로
내보냅니다. 콘티는 대부분 그렇게 공유되기 때문입니다.

입력칸을 나열하는 것보다, 팀이 실제로 부딪히는 두 가지를 짚는 데 무게를 뒀습니다.

- **조가 얼마나 멀리 건너뛰는가** — 반음 수가 아니라 5도권 거리로 잽니다.
  G에서 D는 반음 7개나 떨어져 있지만 5도권으로는 한 칸이라 쉽게 넘어가고,
  G에서 Db는 반음 6개인데 5도권으로는 여섯 칸이라 손이 완전히 달라집니다.
  단조는 나란한장조로 바꿔 셉니다 (Am과 C는 손이 같습니다).
- **분위기가 어떻게 이어지는가** — 빠른 곡에서 느린 곡으로 바로 넘어가거나,
  같은 분위기가 세 곡 넘게 이어지는 자리를 적어 둡니다.

둘 다 "틀렸다"고 말하지 않습니다. 일부러 그렇게 짠 콘티도 많습니다.
현장에서 당황하기 쉬운 자리만 알려 둡니다.

원키와 부를 키를 함께 적으면 `+2반음`처럼 전조를 계산해 줍니다.
`c#`처럼 적어도 `Db`로 알아서 읽습니다.

### 송폼

곡마다 "인트로 - 1절 - 후렴 - 브릿지 x2 - 후렴 - 엔딩" 처럼 한 줄로 적습니다.
자주 쓰는 마디는 단추로 넣습니다. **칸을 나눠 받지 않은 이유**는 현장에서
"후렴 x2", "반절 내려서" 처럼 말로 적는 일이 많기 때문입니다. 적은 송폼은
미리보기·단톡방 복사본·PDF 에 모두 따라갑니다.

### 악보와 PDF 한 개

`supabase/sheets.sql` 을 실행하면 악보를 올려 둘 수 있습니다(PDF·사진, 20MB까지).
올린 악보는 곡마다 골라 붙이고, **콘티 한 장 + 곡 순서대로의 악보**를 PDF 하나로
내려받습니다. 주일 아침에 팀에게 건네는 것은 결국 종이 한 묶음인데, 콘티 따로
악보 따로 보내면 누군가는 반드시 한쪽을 빼뜨립니다.

악보는 콘티가 아니라 **보관함**에 들어갑니다. 같은 곡을 다음 달에 또 부를 때
다시 올리지 않아도 됩니다. 버킷은 **비공개**입니다 — 악보는 출판사 저작물인 경우가
많아 공개 링크로 열어 두면 안 됩니다. 화면에서 열 때는 1시간짜리 서명 주소를 씁니다.

파일은 **브라우저에서 Storage 로 곶장** 올립니다. 서버 액션을 거치지 않는 이유는
서버 액션 요청이 기본 1MB 에서 잘리기 때문입니다. 악보 PDF 는 그보다 큰 일이 흔합니다.
누가 무엇을 올릴 수 있는지는 Storage 정책이 정합니다 — 경로 첫 칸이 자기 uuid 인
파일만 다룰 수 있습니다.

**첫 장은 글자가 아니라 그림입니다.** pdf-lib 의 기본 글꿴에는 한글이 없어, 글자로
넣으려면 한글 글꿴 파일을 몇 MB 받아야 합니다. 캔버스는 브라우저가 이미 가진 글꿴로
한글을 그려 주므로 받을 것이 없습니다. 콘티 첫 장에서 글자를 복사할 일은 없으므로
잃는 것도 없습니다. 뒤에 붙는 악보 PDF 는 원본 그대로 옮겨집니다.

악보 하나가 깨져 있어도 전체를 포기하지 않습니다. 그 악보만 빼고 만든 뒤 무엇을
뺀는지 알려 줍니다 — 주일 아침에 필요한 것은 완벽한 파일이 아니라 당장 쓸 수 있는
파일입니다.

### 계정에 저장

로그인하면 콘티가 계정에 남습니다(`supabase/setlists.sql`). 노트북에서 짜고
주일 아침에 휴대폰으로 여는 것이 이 기능의 이유입니다.

**로그인은 문턱이 아니라 얹는 것입니다.** 열자마자 쓰는 것이 이 도구의 쓸모라,
로그인 없이도 그대로 동작합니다. 적은 내용은 브라우저에 남아 있다가, 로그인하면
그대로 저장할 수 있습니다. 이 화면은 로그인을 서버에서 확인하지 않습니다 — 확인하려면
쿠키를 읽어야 하고, 그 순간 화면이 요청마다 새로 그려져 모두에게 느려집니다.
저장 칸만 따로 물어봅니다.

콘티는 집계하는 자료가 아니라 한 덩어리로 읽고 쓰는 문서라 `jsonb` 한 칸에
담습니다. 목록에 필요한 것(이름·날짜·곡 수)만 밖으로 꺼냈습니다. 브라우저가 보낸
값은 믿지 않고 `reviveSetlist` 로 걸러 다시 만듭니다.

콘티의 주인은 `profiles` 가 아니라 `auth.users` 입니다. 다른 표는 `profiles(id)` 를
가리키지만, 그러면 카카오로 막 들어와 소속을 아직 적지 않은 사람은 저장할 수
없습니다. 소속 확인은 교회 연락처를 볼 때 필요한 것이지, 자기 콘티를 적는 데 받을
문턱이 아닙니다.

## 주보 · 순서지

`/tools/bulletin`. 예배 종류를 고르면 기본 순서가 채워지고, 오른쪽 미리보기가
그대로 인쇄됩니다(A4, 여백 14mm). 브라우저의 "PDF로 저장"을 쓰면 파일로 남습니다.

- 기본 순서: 주일 오전·오후, 수요기도회, 새벽기도회, 금요기도회, 성찬예배
- 비고 칸에 `요3:16`처럼 적고 칸을 벗어나면 `요한복음 3:16`으로 펴집니다
- 편집 화면은 `.no-print`, 지면은 `.print-sheet` 로 나뉘어 인쇄에서 걸러집니다

## 스케치 영상 기획

`/tools/video`. 촬영 전에 무엇을 찍을지 정하고, 편집 구성을 짜서 마크다운으로

- **편집 구성**: 구간별 길이를 더해 목표 길이와 견줍니다. 초과하면 빨갛게 표시됩니다.

## 새 공고 알림

`/alerts`. 지역·직분·근무 형태를 정해 두면 맞는 공고가 올라올 때 메일로 알립니다.
비워 둔 칸은 "전체"를 뜻합니다.

수집이 끝난 뒤 GitHub Actions가 이어서 `npm run notify` 를 돌립니다.
구독 정보를 모두 읽어야 해서 **서비스 롤 열쇠**가 필요하고, 메일 발송에는
**Resend 열쇠**가 필요합니다. 둘 다 GitHub 저장소 Secrets 에 넣습니다.

| Secret | 어디서 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase > Settings > API Keys |
| `SUPABASE_SERVICE_ROLE_KEY` | 같은 곳의 secret key. **공개 저장소이므로 코드에 적지 마세요** |
| `RESEND_API_KEY` | [resend.com](https://resend.com) 무료 가입 |

열쇠가 없으면 알림 단계는 아무것도 하지 않고 넘어갑니다. 수집은 그대로 돕니다.
보낼 대상만 확인하려면 `npm run notify -- --dry` 를 쓰세요.

## 로그인과 회원 승인

카카오·구글로 들어오거나, 메일로 받은 링크로 들어옵니다(매직링크).
어느 쪽이든 저장할 비밀번호가 없습니다.

1. `/login` — 카카오·구글 버튼, 또는 메일 주소로 링크 받기
2. `/account` — 소속 교회·교단·직분 입력 → `대기` 상태로 저장

화면에는 "교단"으로 보이지만 DB 칸 이름은 `presbytery` 입니다. 처음에 노회를
받을 생각으로 지은 이름입니다. 이미 가입한 사람의 값이 그 칸에 들어 있어,
바꾸려면 DB 변경과 배포가 동시에 일어나야 하므로 그대로 두었습니다.
3. 운영진이 승인하면 청빙공고의 교회 연락처를 볼 수 있습니다 (RLS로 DB에서 강제)

승인은 **교회 연락처를 볼 때**만 필요합니다. 콘티 저장처럼 자기 것만 다루는
기능은 로그인만으로 됩니다.

맨 처음에는 승인해 줄 운영진이 없으므로, 첫 사람만
`supabase/bootstrap_admin.sql`을 한 번 실행해 직접 운영진으로 올립니다.

### 카카오·구글 붙이기

둘 다 Supabase 기본 지원입니다(`kakao`, `google`). 네이버는 기본 목록에
없어 커스텀 OIDC를 따로 붙여야 하므로 지금은 넣지 않았습니다.

양쪽 개발자 콘솔에 넣을 **Redirect URI 는 사이트가 아니라 Supabase 주소**입니다.

```
https://pkjmvceeafeekhxxexcn.supabase.co/auth/v1/callback
```

| 곳 | 받을 것 |
|---|---|
| [developers.kakao.com](https://developers.kakao.com) | REST API 키 + Client Secret. 카카오 로그인 활성화, 동의 항목에 닉네임 추가 |
| [Google Cloud Console](https://console.cloud.google.com/apis/credentials) | OAuth 2.0 클라이언트 ID + Secret |

받은 값은 Supabase > Authentication > Sign In / Providers 에 넣습니다.
저장소에는 넣지 않습니다 — 이 저장소는 공개입니다.

#### 카카오는 지금 꺼 두었습니다 (KOE205)

**Supabase 는 카카오 인가 요청에 `account_email` 을 항상 끼워 보냅니다.**
그런데 카카오에서 그 동의항목은 `권한 없음` 으로 잠겨 있어, 누르는 족족
`KOE205 — 설정하지 않은 동의 항목: account_email` 로 끝납니다.

클라이언트에서는 미리 막을 수 없습니다. `signInWithOAuth` 의 `scopes` 는 기본값을
**대체하는 것이 아니라 덧붙입니다** — 직접 확인했습니다.

```
scope = account_email profile_image profile_nickname profile_nickname profile_image
```

그래서 버튼을 `NEXT_PUBLIC_KAKAO_LOGIN` 뒤에 두고 기본으로 꺼 두었습니다.
누르면 반드시 실패하는 버튼을 두면, 들어오는 사람은 사이트가 고장 난 것으로 알게 됩니다.

푸려면 카카오에서 **비즈 앱 전환 → 비즈니스 정보 심사 → 개인정보 동의항목 심사**를
거쳐야 합니다. 사업자번호는 없어도 되지만(본인인증 + 약관 동의로 갈음), **심사가
끝나기를 기다려야 합니다.** 전환에 필요한 앱 아이콘은 `public/kakao-app-icon.png`
에 두었습니다. 통과하면 `account_email` 을 **선택 동의**로 두고 환경변수를
`1` 로 바꾸면 됩니다.

> **카카오는 켰 뒤에도 메일 주소를 주지 않을 수 있습니다.** 선택 동의 항목이기 때문입니다.
> 콘티 저장과 로그인은 그대로 되지만 공고 알림은 메일로 가므로, 주소가 없으면
> `/account` 와 `/alerts` 에서 그 사실을 알려 줍니다.

### 개발 중에는 메일을 이 컴퓨터에서 열어야 합니다

`localhost`로 개발할 때 메일 링크는 `http://localhost:3000/auth/callback` 으로
돌아옵니다. 휴대폰이나 카카오톡·메일 앱에서 누르면 **그 기기의 localhost**를
찾으러 가서 실패합니다("접근할 수 없습니다"). 링크는 사이트를 띄운 컴퓨터의
브라우저에서 열어야 합니다. 배포하면 실제 도메인이 되므로 사라지는 문제입니다.

### 6자리 코드 로그인 (SMTP 붙인 뒤)

휴대폰으로 메일을 보는 사람이 많아 코드 입력 화면도 만들어 뒀지만, 기본으로는
꺼져 있습니다. Supabase 기본 메일은 링크만 보내고, 코드를 넣으려면 메일
템플릿에 `{{ .Token }}` 을 넣어야 하는데 **템플릿 편집은 custom SMTP를 붙여야
열립니다**. 순서는 이렇습니다.

1. Authentication > Emails > SMTP Settings 에서 SMTP 연결 (Resend 등)
2. Confirm sign up / Magic link or OTP 템플릿에 `{{ .Token }}` 추가
3. `.env.local` 에 `NEXT_PUBLIC_EMAIL_OTP=1`

SMTP를 붙이면 무료 기본 메일의 **시간당 2통** 제한도 같이 풀립니다.

Supabase 설정에서 챙겨야 할 것:

- **Authentication > URL Configuration > Redirect URLs** 에 접속 주소를 넣어야
  메일 링크가 사이트로 돌아옵니다. 개발용 `http://localhost:3000/**` 는 등록해
  두었고, 배포하면 그 주소도 같은 형식(`https://도메인/**`)으로 추가하세요.
